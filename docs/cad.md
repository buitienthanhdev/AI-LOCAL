# 3D CAD from text (cad.build, cad.inspect)

Integrates [text-to-cad](https://github.com/earthtojake/text-to-cad) (MIT, Thompson Labs LLC): its `cadgen` package
generates parametric models with build123d on the Open CASCADE kernel and exports STEP, STL, GLB and 3MF.

## Install

```powershell
pwsh scripts/setup-cad.ps1        # uv venv runtime/cad (Python 3.13) + cadgen==0.7.21
pwsh scripts/fetch-references.ps1 # optional: the upstream repo (skills, docs) into references/text-to-cad
```

`runtime/` and `references/` are git-ignored. Without the runtime the tools answer `BACKEND_UNAVAILABLE` with the install line.
Reopen the chat window after installing so it lists the new tools.

## Tools

| Tool | What it does | Policy |
|---|---|---|
| `cad.build` | The planner writes build123d statements ending in `result = <shape>` (`bd` is build123d, millimetres, +Z up). The tool wraps them in a cadgen model script, builds it in `artifacts/<task>/cad/<name>-<time>/`, writes STEP (+ STL / GLB / 3MF), measures the solid and renders an isometric preview. | confirm in `normal`, allow in `trusted` / `full_access` |
| `cad.inspect` | Measures an existing `.step` / `.stp`: bounding box, volume, area, faces, solids, validity, preview. | allow |

Measured and checked by the tool, not by the model's say-so: bounding box, volume, face count, number of solids, validity.
`expected_size_mm` (the size the user asked for, any axis order) fails the call with the measured numbers when the model
differs by more than max(0.5 mm, 2 %); several solids fail unless `assembly` is true. A Python error comes back as the
traceback so the planner changes only the failing line.

## Planner support

* Planner rule 17 and the `cad-3d` playbook (`skills/cad-3d.md`): constants for every dimension, primitives, `bd.Pos` / `bd.Rot`,
  boolean operators, fillets after the last boolean, 3D-print clearances.
* Tool group `cad` is offered when the request mentions 3D, STEP, STL, 3MF, GLB, bracket, gear, enclosure and similar words.
* 2D plans and drawings stay with `autocad.*`; pictures stay with `art.*`.

## Tests

`services/python-agent/tests/test_cad_unit.py` (contract, argument check, real builds when `runtime/cad` exists) and the
bench tasks `tests/bench/tasks_cad.json` (generated by `make_cad_tasks.py`).

# AutoCAD residential drawing specification layer (autocad.profile_check / validate_model / compare_revisions / plan_operation / report)

Implements the testable, AutoCAD-independent parts of `docs/specs/SPEC_VE_BAN_VE_KY_THUAT_NHA_AUTOCAD.txt`
(code in `services/python-agent/lga_worker/autocad/`: `standards`, `provenance`, `layers`, `geom2d`, `validation`,
`safety`, `revision`, `report`, `spec_tools`). All five tools are offline; they never open or change a drawing.

| Tool | Spec | What it does |
|---|---|---|
| `autocad.profile_check` | 1 | Project Standards Profile: missing / assumed / invalid / legally unverified fields and clarification questions (options, multi-select, "Khac", "Giu UNKNOWN"). Legal fields get no suggested options. |
| `autocad.validate_model` | 7, 15, 18 | 31 rules (rule_id, scope, severity, PASS/FAIL/WARN/NOT_RUN, evidence) over the intermediate model or `autocad.get_entities` output. Per-purpose tolerances in mm; waivers need approver, reason, date, scope; a BLOCKER is never waivable; no data means NOT_RUN. |
| `autocad.compare_revisions` | 16 | added / modified / deleted / conflicted by id, geometry, layer, properties; uncertain id mapping blocks mass delete; optional revision-log rows. |
| `autocad.plan_operation` | 14, 17 | Dry run: idempotency key + entity marker, confirmation reasons (bulk delete, purge, explode, unit change, layer structure, overwrite). |
| `autocad.report` | 19 | Report sections INPUT_REVIEW ... LIMITATIONS; FINAL_STATUS (DRAFT, CAD_VALID, DRAWING_CHECKED, COORDINATED, CODE_REVIEWED) computed from evidence; outputs listed only if on disk; optional `.md` + `.json` files. |

Safety wired into existing tools: `autocad.save`, `export_dxf`, `export_pdf` write an operation record
(`artifacts/<task>/autocad/operations.jsonl`), make a SHA-256-verified backup (`.lga_backups/`) before an overwrite and
restore it if the write fails; the result carries `operation_id` and `backup`.

## Honest limits

* The spec layer was verified by unit tests (`tests/test_autocad_spec_unit.py`); the view tools also had a live run (below). No code compliance is checked,
  and no DWG was re-opened from disk.
* `dwg_opened_in_autocad` / `pdf_rendered_checked` are flags the caller sets from earlier tool results; the report checks file
  existence and DWG/PDF header bytes itself and lists these flags as unverified. Code review and issue approval come only from
  human-written JSON files; an issue status is impossible without both and without CODE_REVIEWED.
* Default tolerances are working defaults (mm per purpose), not standards; set them per project. Stair/riser limits are applied
  only when passed from a verified profile. No legal, structural, fire or accessibility compliance is checked.
* Not implemented: reading DWG/PDF/IFC directly into the model (only `autocad.get_entities` output, types inferred from layer
  names), (elevation/section generation now exists for generated houses, see below), idempotency markers written into AutoCAD entities (journal-level only), PDF visual checks,
  block/attribute, CTB/STB and plot-setting inspection beyond the supplied `meta` inventory.

# House views from one shared model (autocad.house_model / draw_elevation / draw_section / draw_schedules)

Code: `lga_worker/autocad/housemodel.py` (pure model), `houseviews.py` (pure view primitives), `provider.draw_prims`
(COM drawing), rules in `validation.py`, tools in `tools/autocad.json` + `lga_worker/tools/autocad.py`.

* `build_house_model(params)` runs `floorplan.plan_house` (same parameters as `autocad.draw_floor_plan`) and returns levels
  (ground, +0.000 floor, ceiling, roof, ridge/parapet), wall runs (thickness, centre line, facade), doors/windows with unique
  codes D1.. / W1.., sizes, sill heights and host wall, rooms with a closed boundary (L-shaped when a bedroom has an alcove) and
  the area recomputed from it (centre-line rule), roof, and the list of assumptions. The plan symbols' numbers, the elevations,
  the section and the schedules all read this one object; nothing is typed twice.
* Elevations (front/rear/left/right), sections (cut line, marker A-A, slabs, hatched cut walls split around openings, stair if the
  model has one, level marks, clear heights) and the door/window/room tables are `Prim` lists on standard A-* layers (mapped by
  `layers.view_layers` / optional `layer_map`), model space 1:1, everything ByLayer. Each view also returns a record MEASURED from
  its own primitives (opening rectangles, level lines and label text, dimension values, table cell text, marker line).
* `autocad.house_model(views=[records])` returns the intermediate model for `autocad.validate_model` / `autocad.report`.
* New rules (COORDINATION, ERROR; NOT_RUN without data or units): `COORD.ELEVATION_MATCHES_PLAN`,
  `COORD.SCHEDULE_MATCHES_ELEVATION`, `COORD.LEVELS_ELEVATION_SECTION`, `COORD.SECTION_MARKER_VIEW` (a section without a marker is a
  WARNING), `COORD.ROOM_TABLE_AREA`. 36 rules in all. `COORD.AREA_RECOMPUTED` now ignores a table total line.
* Safety: the draw tools write an operation record (`operations.jsonl`); `export_path` writes go through the backup-before-overwrite
  guard; a drawing call fails with VERIFICATION_FAILED when AutoCAD's entity count differs from what was sent. Not idempotent.
* Working defaults (storey 3.3 m, plinth 0.45, slab 0.1, door 2.1/2.4, window 1.2 at sill 0.9, narrow window 0.6 at 1.5, roof 30 deg,
  overhang 0.6, parapet 0.6, wall 0.2/0.1 m, datum +0.000 = floor 1) are flagged ASSUMED with a source note in the model and
  `data.assumptions`; arguments of the caller become PROVIDED. They are not code requirements; no structural design, no
  fire/accessibility/glass compliance is checked or claimed. Hatches are graphic symbols only.
